# Protocol Retirement Disposition

Every behavior ID whose traceability row names a protocol suite has exactly one
row here, recording whether PR 11.5 retires it with the protocol or remaps it to
a surviving home.

The gate is `tests/baseline/protocol-disposition.test.js`. Its input is a frozen
29-ID literal in that file, never a query over `traceability.md` — a
selector-derived input would empty exactly when PR 11.5 deletes the suites, and
the gate would pass vacuously against the event it exists to guard.

`Target` names a **file**, not a `PATH::SELECTOR`. The selector is PR 11.5's to
write; `TRACEABILITY-TESTS-01` resolves it once it exists.

The discriminator is not which suite owns the ID today. For each row, the
contract text in `behavioral-inventory.md` either describes the **transport** —
the serialized protocol-v1 envelope, the response document, and the validator
that reads it — or a **domain rule merely expressed over** that transport.
Transport retires; a domain rule remaps. Where the honest remap target is a file
that does not exist yet, the row retires and PR 11.5 re-establishes the coverage
under a new ID, because a remap to a speculative file would reintroduce exactly
the vacuity this gate exists to prevent.
